# Level 4: Domain Events and Integration Events

This level explores the distinction between domain events and integration events, and how `EricksonLopez.Outbox` bridges the gap.

## Domain Events vs. Integration Events

| Aspect | Domain Event | Integration Event |
|---|---|---|
| **Scope** | Within a single bounded context | Across bounded contexts / services |
| **Transport** | In-memory (MediatR, `INotificationHandler`) | Message broker (RabbitMQ, Kafka, etc.) |
| **Schema Coupling** | Internal — can change freely | Public contract — versioning required |
| **Serialization** | Optional | Required (JSON, Protobuf, etc.) |

`EricksonLopez.Outbox` operates exclusively on **Integration Events** — the events that cross service boundaries via a physical message broker.

## Designing Integration Events

### The `IIntegrationEvent` Interface and `[OutboxMessage]` Attribute

The library provides an optional `IIntegrationEvent` marker interface that enforces standard properties (`EventId` and `OccurredOn`) on your public contracts.

Every type stored in the outbox must be decorated with `[OutboxMessage]`:

```csharp
using EricksonLopez.Outbox.Contracts;

[OutboxMessage("order-created-v1")]
public record OrderCreatedEvent(
    Guid EventId,
    string CustomerId,
    decimal Total,
    DateTimeOffset OccurredOn) : IIntegrationEvent;
```

The **alias** (`"order-created-v1"`) is:
- Stored in the `type` column of the `outbox.messages` table
- Used by the `IOutboxMessageTypeResolver` to reconstruct the CLR type during dispatch
- Must be **unique** across all registered message types
- Should include a version suffix for safe schema evolution

> [!NOTE]
> `IIntegrationEvent` is **optional**. The outbox does not require it — `[OutboxMessage]` alone is sufficient. The interface is useful in DDD environments where you want to enforce that every event contract carries a standard `EventId` and `OccurredOn`.

### Event Versioning Strategy

```csharp
// Version 1 — minimal contract
[OutboxMessage("order-created-v1")]
public record OrderCreatedEventV1(Guid OrderId, string CustomerId);

// Version 2 — adds a new non-breaking field
[OutboxMessage("order-created-v2")]
public record OrderCreatedEventV2(Guid OrderId, string CustomerId, decimal Total);
```

> [!IMPORTANT]
> Never change an existing alias or remove fields from a published event type.
> Consumers may still have unprocessed V1 messages in their queues.

## Message Metadata

Every outbox message carries structured metadata. The `MessageMetadata` type is a **readonly struct** — it must be constructed via its constructor, not an object initializer:

```csharp
using EricksonLopez.Outbox;

// MessageMetadata is a readonly struct. Use the constructor:
var metadata = new MessageMetadata(
    correlationId: correlationId,  // Optional: W3C correlation ID for distributed tracing
    causationId: causationId,      // Optional: ID of the event/command that triggered this
    messageType: null              // Leave null — overridden by IOutbox during processing
);

await _outbox.StoreAsync(
    new OrderCreatedEvent(orderId, customerId, total),
    txContext,
    metadata,
    deliverAt: null, // null = deliver immediately; DateTimeOffset = scheduled delivery
    ct);
```

### Metadata Fields

| Field | Purpose |
|---|---|
| `CorrelationId` | Traces a business operation across multiple services (W3C TraceContext compatible). |
| `CausationId` | Links this event to the command or event that caused it (causal chain). |
| `MessageType` | The alias string — set automatically by `IOutbox` from `[OutboxMessage]`. |

### Fluent Alternative

Using the `Publish()` builder is usually cleaner than the `StoreAsync` overload with explicit metadata:

```csharp
await _outbox
    .Publish(new OrderCreatedEvent(orderId, customerId, total))
    .WithTransaction(txContext)
    .WithCorrelationId(Activity.Current?.TraceId.ToString())
    .WithCausationId(previousEventId)
    .WithHeader("x-tenant-id", tenantId)
    .StoreAsync(ct);
```

## Source Generators and AOT

The `OutboxTypeMappingGenerator` (incremental source generator, package `EricksonLopez.Outbox.SourceGenerators`) scans your assembly at compile time for all `[OutboxMessage]` decorated types and generates:

1. **Type mapping registration** — Links aliases to CLR types without reflection
2. **A `UseGeneratedTypes()` extension method** — Registers the generated `IOutboxMessageTypeResolver`

```csharp
// Auto-generated — do NOT edit
// Generated by EricksonLopez.Outbox.SourceGenerators

namespace EricksonLopez.Outbox.Generated;

internal static class GeneratedTypeMappingExtensions
{
    public static OutboxOptions UseGeneratedTypes(this OutboxOptions options) { ... }
}
```

```csharp
// Usage in Program.cs:
using EricksonLopez.Outbox.Generated;

builder.Services.AddOutbox(options =>
{
    options.UseGeneratedTypes(); // Resolves all [OutboxMessage] types at compile time
    options.UseSerializer(new NativeAotJsonSerializer(MyJsonContext.Default));
});
```

> [!NOTE]
> Due to a Roslyn limitation (see [ADR-0001](../adr/0001-limitacion-source-generator-json.md)),
> the `JsonSerializerContext` must be declared manually by the consumer.
> The source generator emits a commented template to simplify this.

### Roslyn Analyzer Protection

The `EricksonLopez.Outbox.Analyzers` package enforces correct usage at compile time:

| Diagnostic | Description |
|---|---|
| **OUTBOX001** | A type implements `IIntegrationEvent` but is missing `[OutboxMessage]`. |
| **OUTBOX002** | A `StoreAsync()` call is made with a type not registered with `[OutboxMessage]` and not in the type resolver. |

## `InboxConsumerAttribute` — Source-Generated Inbox

Mark a method as an Inbox consumer handler, and the source generator wraps it with idempotency checks and transaction management:

```csharp
using EricksonLopez.Outbox.Contracts;

public class BillingMessageHandler
{
    private readonly BillingDbContext _db;

    public BillingMessageHandler(BillingDbContext db) => _db = db;

    // The source generator generates the idempotency wrapper around this method.
    // EventAlias must match the [OutboxMessage] alias of the producer event.
    [InboxConsumer("order-created-v1")]
    public async Task HandleOrderCreatedAsync(OrderCreatedEvent evt, CancellationToken ct)
    {
        // No idempotency boilerplate needed here — the generator handles it.
        var invoice = new Invoice { OrderId = evt.OrderId, Amount = evt.Total };
        _db.Invoices.Add(invoice);
        await _db.SaveChangesAsync(ct);
    }
}
```

> [!NOTE]
> `[InboxConsumerAttribute]` source generation is an incremental feature. When source generators are not available, use `IInboxIdempotencyChecker.ShouldProcessAsync()` directly (see [Level 3](level-03-real-use-cases.md)).
