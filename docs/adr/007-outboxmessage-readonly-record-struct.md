# ADR-007: Use `readonly record struct` as the base type for `OutboxMessage`

## 1. Title and Status
**Immutable Base Type for Outbox Messages (HISTORICAL)**
*Status:* ~~Approved and Implemented~~ **SUPERSEDED by [ADR-012](012-outboxmessage-positional-ctor-breaking-change.md)**

> [!WARNING]
> This ADR is **superseded**. The implementation was changed from `readonly record struct` to `sealed record`
> before the v1.0.0 release to accommodate `ReadOnlyMemory<byte>` payload storage and EF Core
> entity materialization. This document is preserved as historical context only.
> See [ADR-012](012-outboxmessage-positional-ctor-breaking-change.md) for the current decision.

## 2. Context and Motivation
`OutboxMessage` is the central type of the system. It is hydrated from the database, passed to the broker publisher, and then discarded. Its lifecycle is short and predictable. The choice between `class`, `record`, `struct`, and `record struct` directly impacts GC pressure and throughput.

## 3. Decision
Use `readonly record struct`.

## 4. Rationale

| Option | Heap Allocation | Copy Semantics | Equality | Mutability |
|--------|----------------|----------------|----------|------------|
| `class` | Yes | Reference | Reference | Mutable |
| `record class` | Yes | Reference | Value (generated) | Immutable |
| `struct` | No (if not escaped) | Value | Manual | Mutable |
| `readonly record struct` | **No (if not escaped)** | **Value** | **Value (generated)** | **Immutable** |

`readonly record struct` is the only option that combines:
- **Zero heap allocation** when it doesn't escape to the heap.
- **Value equality** generated by the compiler.
- **Immutability** by default (`readonly`).
- **Deconstruction** and `with` expressions out of the box.

## 5. Trade-offs
- **Boxing**: If passed to an `IEnumerable<object>`, boxing occurs. This is mitigated by using generics (`IReadOnlyList<OutboxMessage>`).
- **Copy cost**: Each assignment copies the fields. With 11 fields, the cost is ~88 bytes per copy. This is acceptable given the short lifecycle.
- **`ReadOnlyMemory<byte>` Payload**: Does not copy the underlying bytes — only the span header (16 bytes). Highly efficient.

## 6. Consequences
- The dispatcher never heap-allocates an `OutboxMessage` during normal processing.
- NativeAOT: `record struct` types are fully compatible.
- Serializers can map directly from `NpgsqlDataReader` without intermediate heap allocations.
