# ADR-002: Zero-Allocation Models (Immutable by Default)

## 1. Title and Status
**Immutable and Value-Type Data Structures (`readonly record struct`)**
*Status:* Approved and Implemented in `EricksonLopez.Outbox`.

## 2. Context and Motivation
In transactional messaging systems processing thousands of messages per second (High-Throughput), the biggest bottleneck in .NET is typically not the CPU, but the Garbage Collector (GC). The constant creation of generic `class` objects (`MessageEnvelope<T>`, `Metadata`, `DispatchResult`) floods the Gen 0 Heap, causing micro-pauses (GC Pauses) that degrade the p99 latency SLA.
The motivation is to guarantee a **Zero-Allocation Hot Path** from the moment `IOutbox.StoreAsync()` is invoked until the message touches the database.

## 3. Evaluated Alternatives
1. **POCO Classes (`class`):** The industry standard. Easy to use, but comes with a high cost on the Heap.
2. **Object Pooling (`ObjectPool<T>`):** Reusing instances. Complex to implement correctly without introducing race conditions or memory leaks, and is hostile towards the concurrent collector.
3. **Immutable Structs (`readonly record struct`, `ref struct`):** Allocated on the Stack or passed via registers, memory is instantly freed upon exiting the scope (Zero GC).

## 4. Advantages
* **GC Performance:** ZERO pressure on the garbage collector in the main flow.
* **Immutability:** Guarantees that a Payload or its Metadata cannot be altered in memory by a rogue Worker before being saved to the DB (SOLID, Predictability).
* **Security (Thread-Safety):** By definition, being copy-by-value (passed via in/ref), they are inherently safe for massive concurrency.

## 5. Disadvantages
* **Size (Struct Tearing):** If the struct exceeds 16-24 bytes, passing it by value through many method calls can be more costly than passing a pointer.

## 6. Trade-offs
To mitigate the copy-by-value cost of large structs, the design uses `ref struct` for the `OutboxMessageBuilder`, and ensures that heavy metadata (Headers) use efficient immutable collections (`ImmutableDictionary<string, string>`) passed internally by reference.

## 7. Performance Impact
* **Massive:** Dramatic increase in throughput. Internal benchmarks will estimate linear dispatch scalability without queue latency generated by the GC.

## 8. NativeAOT Impact
* **Excellent:** NativeAOT loves static and deterministic value structures. It avoids the Virtual Method Table (VTable) overhead mandatory in classes.

## 9. Maintainability Impact
* **Neutral:** Modern C# (`record struct`) makes writing immutable types just as concise as a traditional class.

## 10. Extensibility Impact
* **Limited:** Structs do not support inheritance (only interfaces). However, in Clean Architecture, domain DTOs should not inherit, so favoring *Composition over Inheritance* aligns perfectly with our design.

## 11. Developer Experience (DX) Impact
* **Transparent:** For the end-user, calling `.StoreAsync(new Event())` is identical regardless of whether we use the Heap or the Stack under the hood. The complexity is hidden within the framework.
