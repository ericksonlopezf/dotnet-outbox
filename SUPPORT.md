# Support & Getting Help

Welcome to the `EricksonLopez.Outbox` community! If you need help, encounter a bug, or want to suggest a new feature, this document outlines the best ways to get support.

## 1. Community Support (Free)

For general usage questions, troubleshooting, and architectural advice, please leverage our public community channels.

### GitHub Discussions
The best place to ask questions and share ideas is [GitHub Discussions](https://github.com/ericksonlopezf/dotnet-outbox/discussions).
- Use the **Q&A** category for "How do I do X?" questions.
- Use the **Ideas** category to propose new features before opening an issue.

### GitHub Issues (Bug Reports Only)
If you have found a reproducible bug, please open a [GitHub Issue](https://github.com/ericksonlopezf/dotnet-outbox/issues).
- Ensure you provide a minimal reproducible example (e.g., a link to a separate GitHub repo).
- Include the version of the package, the database engine, and the broker you are using.
- **Do not** use Issues for technical support questions.

## 2. Enterprise Support & Consulting

If you are using `EricksonLopez.Outbox` in a mission-critical production environment and require guaranteed SLAs, private architectural reviews, or custom integrations, we offer Enterprise Support.

Please contact **ericksonlopezf@gmail.com** for inquiries regarding:
- Private Slack/Teams channels with the core maintainers.
- 24/7 Incident response for production outages.
- Custom Plugin Development (e.g., integrating a proprietary in-house message broker).
- High-Throughput Performance Tuning (PostgreSQL/SQL Server optimization).
